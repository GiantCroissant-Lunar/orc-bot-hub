# ADR-0016: A component revision is a presentation unit and a managed unit, with separate lifecycles

- Status: Accepted
- Date: 2026-08-16
- Extends: [ADR-0013](0013-four-tier-bundle-oriented-csharp-architecture.md)
- Related: ADR-0015
- Informed by: [discussion/cordis-osgi.md](../discussion/cordis-osgi.md)

## Context

ADR-0013 settled the tiers and two hard constraints measured on Godot 4.7.1:
Godot cannot unmount a PCK, so nothing unmounts one; and a Godot `Node` pins a
collectible `AssemblyLoadContext`, so nothing Godot-derived enters one.

What it did not say is how a *replacement* works — and the obvious reading, that
"reload the bundle" is one operation, is wrong in a way that will not show up
until it is being debugged live.

## Decision

**A component revision has two units with separate lifecycles.**

```
ComponentRevision r17
├── PresentationUnit          ManagedUnit
│     panel.pck                 Presenter.dll
│     .tscn                     private dependencies
│     theme, icons
│   Godot resource lifecycle  .NET ALC lifecycle
```

Godot's PCK system owns resources and scenes; the ALC owns managed code. Their
caching semantics differ — Godot's own documentation warns that an
already-preloaded resource does not change merely because another pack was
mounted later. Treating them as one primitive means a swap that appears to
succeed while the old scene is still being served from cache.

**Replacement is an ordered transaction, and its final step is proof.**

```
verify manifest + hashes  →  create ALC r18  →  resolve requirements
  →  construct r18 but DO NOT publish  →  validate  →  generation CAS
  →  quiesce r17  →  revoke r17 offers  →  dispose r17 EffectScope
  →  publish r18 offers  →  activate dependents  →  unload r17
       ├── collected      →  success
       └── still alive    →  RestartRequired / Quarantined
```

The order is the content. Constructing before publishing means a revision that
cannot be built never displaces a working one. Revoking offers before disposing
effects means no caller resolves a service whose effects are being torn down.
Unloading last, and **checking that it actually happened**, is what stops a
"successful" reload from leaking a generation each time.

**`EffectScope` is the mechanism that makes unload possible, not tidiness.** A
collectible ALC unloads only when nothing outside it holds a reference in. So an
activation may not freely write `GlobalEvent += Handler` or `registry.Add(this)`;
every registration goes through an owner-scoped effect, and disposing the scope
tears down every host→component reference by construction.

**Resident code never caches a reloadable service reference.** It resolves the
current service per call, against an owner/generation-scoped registry. The prior
attempt reached this same rule and it is worth carrying forward.

**Components do not hold each other's types.** If plugin B caches an object whose
type belongs to plugin A, unloading A now requires B to release it, and the ALC
graph becomes a dependency mesh nobody can reason about. Components publish
services into the resident registry and exchange immutable data.

**Three kinds of extension get three deployment policies**, which is a far more
useful ladder than "plugin or not":

| Extension | Policy |
| --- | --- |
| Trusted, pure managed — presenter, parser, transformer, read-only adapter | Collectible ALC, *if* it passes unload testing |
| Godot-facing — needs `Node`, `Control`, `GraphEdit`, signals | Split: resident Godot adapter + collectible plain-C# behaviour. The Godot side is **not** reloadable |
| Untrusted, native-heavy, or poor unloadability | Separate process. An ALC is **not** a security boundary |

**Generated artifacts are not candidate source.** A candidate's source delta is
the authored input; `.tscn`, `.tres`, `.cs`, and `.pck` are reproducible build
output. Mixing them makes every candidate diff include machine noise and invites
a reviewer to approve generated bytes they cannot read.

## Consequences

- A "reload" is now at least six observable steps with a typed outcome, not a
  boolean. `RestartRequired` and `Quarantined` are ordinary results.
- The unload proof must run **from the exported binary**, not only from
  `dotnet test` or the editor. Exported and editor load-context behaviour differ
  exactly where this decision lives, so a green test in the wrong host proves
  nothing. See RFC-0005.
- Discovery metadata is not free: reflecting custom attributes on component types
  makes the CLR resolve the assemblies defining those attributes, which drags
  attribute assemblies into the shared-identity contract. "Just use attributes"
  has a cost that has to be counted.
- Two units means two manifests and two hashes per revision. That is more
  bookkeeping than one bundle, and it is the price of the swap being debuggable.

## What this ADR does not decide

Dynamic loading remains outside the accepted slice. This ADR describes the
transaction a later slice implements and RFC-0005 measures. Nothing here
schedules it, and the first memory surface (RFC-0004) is deliberately **resident**
so it needs none of this.

The prior attempt's `PluginArchi` / `ServiceArchi` bundle framework is **not**
restored wholesale. Specific rules are carried forward — resolve shared contracts
from the ALC that owns them rather than assuming Default, keep reloadable
payloads free of Godot types, return immutable data rather than component
objects, owner/generation-scoped registration, versioned payload extraction
instead of overwriting files the running process has loaded, and weak-reference
verification after unload. The framework around them is not.

## Alternatives considered

**One bundle, one reload primitive.** Rejected — the two lifecycles have
genuinely different caching and unload semantics, and merging them hides the PCK
cache behaviour behind an apparently successful managed swap.

**Make Godot-derived classes unloadable.** Rejected as impossible rather than
undesirable. Godot's own ALC implementation has resident project code and treats
collectible contexts as a specialised mechanism, not a replacement for its script
system. The composition system is designed *around* Godot, not against it.
